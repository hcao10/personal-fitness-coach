# Cmine Fit 产品界面设计

更新：2026-10-23。设计目标是让用户准备训练、看清动作、记录训练，并在现实条件变化时获得可确认的教练建议。

## 参考与取舍

- [Apple Fitness+](https://www.apple.com/apple-fitness-plus/)：官网与产品介绍把当前任务、训练内容和个人安排分开呈现。借鉴留白、字体层级、单一主操作和完整媒体展示。
- [Fitbod](https://fitbod.me/)：训练安排围绕器械、目标、记录和恢复；动作演示紧邻训练内容。借鉴训练信息与动作指导的关联。
- [Hevy](https://www.hevyapp.com/)：记录训练、建立训练安排和查看进展是主要任务。借鉴执行中的记录优先级。
- [Web Interface Guidelines](https://github.com/vercel-labs/web-interface-guidelines/blob/main/command.md)：用于检查标签、焦点、反馈、触摸目标和减少动态效果的支持。

没有复制参考网站的 Logo、图片或界面。沿用项目原有 `/icon.svg`，作为网站、教练标识和 PWA 图标的统一来源。首页的器械静物图为本次生成；实际动作仍展示原有动作库媒体，不生成动作教学图片。

## 视觉系统

采用白、浅灰、炭黑和深绿。背景 `#f5f5f7`，正文 `#1d1d1f`，次要文字 `#62626a`，主操作 `#216b53`；已有 Logo 保留原色。使用系统字体，省去远程字体加载。间距以 8px 为基础，表单与操作以 44–48px 的触摸高度设计。只有反馈和方案出现时使用短动画；支持 `prefers-reduced-motion`。

设计源分成共享 tokens、导航，以及首页、训练、教练、账号与响应式样式。品牌由 `BrandMark` 复用；导航图标使用同一套线性 SVG。用户界面去除箭头装饰、emoji 和实现说明。

## 页面职责

| 页面 | 用户主要任务 | 主要分区 |
| --- | --- | --- |
| 首页 | 理解产品并开始 | 产品价值、开始入口、真实能力介绍 |
| 入门 | 完成可执行的训练资料 | 分步问题、选项、当前输入的影响、继续 |
| 计划 | 理解并接受安排 | 概要、周日程、动作、开始训练 |
| 今日 | 开始并执行训练 | 今日安排、开始、调整入口、带缩略图的动作列表 |
| 训练中 | 看动作并记录组次 | 单动作演示、细节入口、组次表、休息、前后动作 |
| 动作详情 | 理解动作 | 大图与播放控制、处方、步骤、呼吸、错误、停止条件 |
| 教练 | 提问、审阅并确认方案 | 对话历史、当前对话、训练方案、输入区 |
| 饮食 | 查看目标并记录饮食 | 今日营养、照片或搜索、确认与已记录内容 |
| 进度 | 看趋势并反馈 | 记录、趋势、复盘 |
| 我的 | 管理账号和训练资料 | 档案、计划记录、会员、提醒、数据管理 |

## 教练界面的信息层级

桌面左栏只放历史对话与相关入口；手机通过“历史对话”打开独立对话框。对话不再被每日简报、规则说明或额度卡挤到下方。顶部只保留身份与当前训练入口。

训练方案直接使用后端校验后的 `beforeWorkout` / `afterWorkout`：对比时长和动作数，显示调整后的动作及组次，再给出保持或应用按钮。确认后显示“已生效”和今日训练入口，不再把同一方案分别以正文和卡片重复展示。

完整模型说明、依据、来源与非紧急边界保留在方案下方，用户按需查看。高风险回复保持可见；涉及疼痛、停止训练和紧急处理的限制直接显示。该标识会随流式事件与数据库消息一同保存和恢复。

自动滚动只作用于对话容器，并从最新回复开头展示；不会把整页标题卷进顶部导航下。中文输入法选词时回车不发送。发送、停止、应用中、失败和已生效都有相应状态。

## 训练执行细节

动作演示可以暂停和播放，并尊重减少动态效果的系统偏好。图片预留尺寸；静态图和 GIF 分开处理加载失败，避免一张图失败就隐藏另一个可用资源。

训练记录按输入顺序保存；最后一次失败会恢复到上一次已保存的数据。保存未结束时不允许完成训练。休息计时按截止时间计算，返回前台时重新计算剩余时间。处方中的工作组不会因用户经验而自动变成热身组。

今日训练优先使用已确认的单次训练覆盖；“我的”页也读取同一真实今日安排。周计划仍显示模板，以避免把一次临时调整误认为整周变更。

## 验证方式

使用 ui-ux-pro-max、frontend-design、web-design-guidelines 和 React 最佳实践进行设计与检查，使用 imagegen 生成首页素材。通过生产真实登录验证模型调整，并用浏览器检查桌面和 390px 手机视口；测试证据和发布记录见 `acceptance/` 与生产发布说明。浏览器检查不能代替真实训练中的长期可用性测试。
