# 访客与账户模式

产品页面共用账户与存储状态提示；首页提供两种模式的对比。中文和英文同步维护。

| 能力 | 访客 | Cmine ID 登录后 |
|---|---|---|
| 规则训练计划、动作指导、训练记录 | 当前浏览器本地保存，不调用 AI | 使用现有账户训练流程 |
| AI 计划、AI 对话、AI 饭菜照片识别、AI 复盘 | 不允许；展示登录入口 | 仍按服务配置、账户权限、额度和既有确认流程执行 |
| 饮食记录、条码查询、账户历史与云端数据 | 沿用既有登录要求 | 保存到账户的记录可由同一账户在其他设备访问 |

本地访客数据不会自动跨设备同步，清除浏览器站点数据会丢失。已有建档流程会在同一设备登录后合并本地资料草稿，不代表访客的全部计划或训练记录都会自动导入云端。界面不得承诺自动上传或自动迁移全部记录。

AI 入口继续使用 `beginCmineLogin` 和既有 Cmine ID OAuth/PKCE/会话校验。登录按钮保留当前页面或训练上下文；悬浮教练同时保留当前提问草稿。未配置账户时不展示无法工作的登录按钮。

服务端认证实现和 AI 运行逻辑没有修改。`tests/anonymous-ai.test.mjs` 使用真实本地 SQL 和正式构建，覆盖无会话及伪造会话访问两个计划端点、教练会话/消息、照片上传/识别、复盘生成、提案采纳：均返回 `401 AUTH_REQUIRED`，外部调用次数为零，账户记录及额度表保持不变。

包装食品沿用 `@zxing/browser` 摄像头条码读取与 Open Food Facts v3 商品/营养查询、缓存和手动录入。不调用 AI。食品库可能缺少商品或字段，确认份量与营养来源后才入账。此次未新增扫描库或修改查询逻辑。
